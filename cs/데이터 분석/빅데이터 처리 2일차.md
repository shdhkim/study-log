# Kafka · HDFS · Spark · Data Warehouse 쉽게 이해하기

## 0. 전체 그림부터 보기

쇼핑몰 서비스를 예로 들어보자.

사용자가 상품을 조회하거나 주문하면 서버에서 이벤트가 발생한다.

```text
사용자
  ↓
쇼핑몰 Spring 서버
  ↓
Kafka
  ↓
┌───────────────┬────────────────┐
↓               ↓                ↓
실시간 알림      HDFS 저장         Spark 처리
                                  ↓
                              Data Warehouse
                                  ↓
                              BI / 대시보드
```

| 기술           | 역할                                | 쉽게 비유                      |
| -------------- | ----------------------------------- | ------------------------------ |
| Kafka          | 데이터를 받아 여러 시스템에 전달    | 고속 컨베이어 벨트             |
| HDFS           | 대용량 파일을 여러 서버에 분산 저장 | 여러 창고를 합친 거대한 저장소 |
| Spark          | 데이터를 여러 서버에서 병렬 처리    | 여러 작업자가 동시에 계산      |
| Data Warehouse | 분석하기 좋은 형태로 데이터를 저장  | 분석 전용 데이터 창고          |

# 1. Kafka는 왜 필요한가?

사용자가 주문했다고 해보자.

Kafka가 없다면 주문 서버가 직접 여러 시스템을 호출할 수도 있다.

```text
주문 서버
 ├─ 결제 서버 호출
 ├─ 문자 서버 호출
 ├─ 포인트 서버 호출
 ├─ 로그 서버 호출
 └─ 통계 서버 호출
```

연결 대상이 많아질수록 주문 서버가 복잡해지고, 통계 서버 장애가 주문 처리에 영향을 줄 수도 있다.

Kafka를 중간에 두면 다음처럼 분리할 수 있다.

```text
             ┌→ 문자 서비스
주문 서버 → Kafka → 포인트 서비스
             ├→ 로그 저장 서비스
             └→ 통계 서비스
```

주문 서버는 Kafka에 **주문이 발생했다는 이벤트**를 넣고, 필요한 시스템들이 각자 읽는다.

# 2. Kafka 기본 구조

```text
Producer → Topic → Partition → Consumer
```

예를 들어 주문 이벤트는 다음 JSON일 수 있다.

```json
{
  "orderId": 1001,
  "userId": 30,
  "productId": 501,
  "price": 120000,
  "createdAt": "2026-08-16T18:00:00"
}
```

- **Producer**: Kafka에 데이터를 넣는 프로그램
- **Topic**: 메시지 종류를 구분하는 논리적 공간
- **Partition**: Topic을 병렬 처리하기 위해 나눈 조각
- **Consumer**: Kafka 데이터를 읽는 프로그램
- **Offset**: Consumer가 어디까지 읽었는지 나타내는 위치

# 3. Spring Boot Kafka Producer 예제

## application.yml

```yaml
spring:
  kafka:
    bootstrap-servers: localhost:9092
    producer:
      key-serializer: org.apache.kafka.common.serialization.StringSerializer
      value-serializer: org.apache.kafka.common.serialization.StringSerializer
```

## OrderEvent.java

```java
public class OrderEvent {
    private Long orderId;
    private Long userId;
    private Long productId;
    private Long price;

    public OrderEvent(Long orderId, Long userId, Long productId, Long price) {
        this.orderId = orderId;
        this.userId = userId;
        this.productId = productId;
        this.price = price;
    }

    public Long getOrderId() { return orderId; }
    public Long getUserId() { return userId; }
    public Long getProductId() { return productId; }
    public Long getPrice() { return price; }
}
```

## Producer

```java
@Service
public class OrderProducer {

    private final KafkaTemplate<String, String> kafkaTemplate;
    private final ObjectMapper objectMapper;

    public OrderProducer(KafkaTemplate<String, String> kafkaTemplate,
                         ObjectMapper objectMapper) {
        this.kafkaTemplate = kafkaTemplate;
        this.objectMapper = objectMapper;
    }

    public void send(OrderEvent event) throws JsonProcessingException {
        String json = objectMapper.writeValueAsString(event);

        kafkaTemplate.send(
            "order-topic",
            event.getOrderId().toString(),
            json
        );
    }
}
```

호출:

```java
OrderEvent event = new OrderEvent(
    1001L,
    30L,
    501L,
    120000L
);

orderProducer.send(event);
```

이제 `order-topic`에 주문 메시지가 들어간다.

# 4. Topic과 Partition

```text
order-topic

Partition 0 → 주문 1001, 1004, 1007
Partition 1 → 주문 1002, 1005, 1008
Partition 2 → 주문 1003, 1006, 1009
```

Partition이 여러 개면 Consumer 여러 개가 병렬로 처리할 수 있다.

```text
Partition 0 → Consumer 1
Partition 1 → Consumer 2
Partition 2 → Consumer 3
```

같은 Consumer Group 안에서 하나의 Partition은 한 Consumer가 담당한다.

# 5. Kafka Consumer 코드

```java
@Service
public class OrderConsumer {

    @KafkaListener(
        topics = "order-topic",
        groupId = "order-statistics-group"
    )
    public void consume(String message) {
        System.out.println("Kafka message = " + message);
    }
}
```

Kafka는 메시지를 Consumer가 읽었다고 즉시 없애는 단순 큐와 다르다.
보관 기간(retention) 동안 디스크에 유지할 수 있다.

```text
Partition 0

offset 0 → 주문1001
offset 1 → 주문1004
offset 2 → 주문1007
offset 3 → 주문1010
```

Consumer가 offset 2까지 처리했다면 다음에는 offset 3부터 읽으면 된다.

# 6. HDFS는 무엇인가?

HDFS = **Hadoop Distributed File System**.

여러 서버의 HDD/SSD를 이용해 하나의 거대한 분산 파일 시스템처럼 사용하는 기술이다.

예를 들어 500MB `orders.csv`가 있다고 하자.

```text
orders.csv 500MB
        ↓
Block A 128MB
Block B 128MB
Block C 128MB
Block D 나머지
```

## DataNode와 Block의 차이

```text
DataNode = 실제 저장 서버
Block    = 파일을 나눈 데이터 조각
```

비유하면:

```text
DataNode = 창고
Block    = 창고 안의 박스
```

예:

```text
DataNode1
 ├─ Block A
 ├─ Block C
 └─ Block E

DataNode2
 ├─ Block B
 ├─ Block D
 └─ Block A 복제본
```

---

# 7. HDFS 복제

Replication Factor가 3이면 동일한 Block을 여러 DataNode에 저장한다.

```text
Block A
 ├─ DataNode1
 ├─ DataNode4
 └─ DataNode7
```

DataNode1이 고장 나도:

```text
DataNode1 ❌
DataNode4 → Block A 있음
DataNode7 → Block A 있음
```

계속 읽을 수 있다.

복제본은 계산을 세 번 하기 위한 것이 아니다. **장애 대응과 데이터 지역성**을 위한 것이다.

---

# 8. NameNode 역할

NameNode는 파일의 메타데이터와 Block 위치를 관리한다.

```text
/orders/2026/orders.csv

Block A → DataNode1, DataNode4, DataNode7
Block B → DataNode2, DataNode3, DataNode6
Block C → DataNode1, DataNode5, DataNode8
```

사용자는 파일 하나를 보는 것 같지만 실제 데이터는 여러 서버에 나뉘어 있다.

# 10. MapReduce는 무엇인가?

HDFS에 10TB 주문 데이터가 있다고 하자.
서버 한 대로 계산하기보다 여러 서버에 나눠 계산한다.

상품 이름 개수 세기:

```text
TV
PHONE
TV
TABLET
PHONE
TV
```

Map:

```text
TV     → (TV, 1)
PHONE  → (PHONE, 1)
TV     → (TV, 1)
TABLET → (TABLET, 1)
PHONE  → (PHONE, 1)
TV     → (TV, 1)
```

Shuffle:

```text
TV     → [1, 1, 1]
PHONE  → [1, 1]
TABLET → [1]
```

Reduce:

```text
TV     → 3
PHONE  → 2
TABLET → 1
```

복제본이 3개 있어도 논리적 Block A는 한 번만 처리한다.
스케줄러가 Block A가 존재하는 적절한 서버에서 Map 작업을 수행한다.

# 11. Spark는 무엇인가?

Spark는 **대용량 데이터를 여러 서버에서 병렬로 계산하는 분산 처리 엔진**이다.

```text
HDFS = 저장
Spark = 계산
```

예:

```text
HDFS의 10TB 주문 데이터
          ↓
        Spark
          ↓
상품별 매출
회원별 구매금액
날짜별 주문량
이상거래 탐지
데이터 전처리
```

Spark는 Python(PySpark), Scala, Java, Spark SQL 등으로 사용할 수 있다.

---

# 12. MapReduce와 Spark 차이

MapReduce는 전통적으로 중간 결과를 디스크에 많이 기록하는 구조다.

```text
Map
 ↓
디스크
 ↓
Reduce
 ↓
디스크
```

Spark는 연산을 DAG로 구성하고, 필요한 경우 데이터를 메모리에 유지하면서 다음 연산으로 넘길 수 있다.

```text
읽기 → filter → map → groupBy → join → aggregate
```

따라서 반복 연산, 복잡한 데이터 파이프라인, 스트리밍 처리 등에 유리하다.

# 16. Data Warehouse(DW)는 무엇인가?

DW는 **분석을 위해 여러 시스템의 데이터를 모아놓은 저장 시스템**이다.

쇼핑몰에는 다음 운영 DB가 따로 있을 수 있다.

```text
회원 DB
주문 DB
상품 DB
결제 DB
배송 DB
```

그런데 회사가 다음 질문을 할 수 있다.

> 최근 3년간 20대 서울 사용자가 가장 많이 구매한 상품 카테고리를 월별로 보여줘.

운영 DB 여러 개에 계속 대형 JOIN/집계를 수행하면 서비스 DB에 부담이 생긴다.

그래서 분석용으로 데이터를 따로 모은다.

```text
회원 DB ─┐
주문 DB ─┤
상품 DB ─┼→ ETL/ELT → Data Warehouse
결제 DB ─┤
배송 DB ─┘
```

# 17. OLTP와 OLAP

운영 DB는 보통 OLTP 성격이 강하다.

```text
주문 등록
결제 상태 변경
회원정보 수정
재고 감소
```

즉 INSERT / UPDATE / 짧은 SELECT가 중요하다.

DW는 OLAP 성격이 강하다.

```sql
SELECT
    region,
    product_category,
    SUM(price)
FROM sales
WHERE order_date >= DATE '2026-01-01'
GROUP BY
    region,
    product_category;
```

대량 조회와 집계가 중요하다.

대표적인 DW 계열 서비스로는 Amazon Redshift, Google BigQuery, Snowflake, Azure Synapse Analytics 등이 있다.

# 19. Kafka + Spark 실시간 처리

```text
Spring 주문 서버
       ↓
Kafka
       ↓
Spark Structured Streaming
       ↓
실시간 집계
       ↓
DW
```

Spark가 Kafka 데이터를 읽는 예:

```python
from pyspark.sql import SparkSession
from pyspark.sql.functions import col

spark = (
    SparkSession.builder
    .appName("KafkaOrderStreaming")
    .getOrCreate()
)

kafka_df = (
    spark.readStream
    .format("kafka")
    .option("kafka.bootstrap.servers", "localhost:9092")
    .option("subscribe", "order-topic")
    .load()
)

message_df = kafka_df.select(
    col("value").cast("string")
)

query = (
    message_df
    .writeStream
    .format("console")
    .start()
)

query.awaitTermination()
```

# 20. Kafka JSON을 Spark DataFrame으로 변환

Kafka 메시지:

```json
{
  "orderId": 1001,
  "userId": 10,
  "product": "TV",
  "price": 1000000
}
```

PySpark:

```python
from pyspark.sql.functions import from_json, col
from pyspark.sql.types import (
    StructType,
    StructField,
    LongType,
    StringType
)

schema = StructType([
    StructField("orderId", LongType()),
    StructField("userId", LongType()),
    StructField("product", StringType()),
    StructField("price", LongType())
])

parsed_df = (
    kafka_df
    .select(
        from_json(
            col("value").cast("string"),
            schema
        ).alias("data")
    )
    .select("data.*")
)
```

결과 DataFrame:

```text
orderId | userId | product | price
1001    | 10     | TV      | 1000000
```

# 22. Kafka → HDFS 저장

원본 주문 이벤트를 장기 보관하고 싶다면 Spark를 통해 HDFS에 Parquet으로 기록할 수 있다.

```python
query = (
    parsed_df
    .writeStream
    .format("parquet")
    .option("path", "hdfs:///data/order-events")
    .option(
        "checkpointLocation",
        "hdfs:///checkpoint/order-events"
    )
    .start()
)

query.awaitTermination()
```

HDFS에는 예를 들어:

```text
/data/order-events/
 ├─ part-00001.parquet
 ├─ part-00002.parquet
 └─ part-00003.parquet
```

처럼 저장된다.

# 23. 왜 Parquet을 많이 쓰나?

CSV는 행 기반 텍스트 파일이다.
Parquet은 컬럼 기반 포맷이기 때문에 분석 시 필요한 컬럼만 효율적으로 읽기 좋다.

예를 들어 다음 컬럼이 있어도:

```text
orderId
userId
product
price
createdAt
```

분석에서 `product`, `price`만 필요하다면 Parquet은 필요한 컬럼 중심으로 읽을 수 있어 대용량 분석에 유리하다.

# 24. 완전한 쇼핑몰 실무 시나리오

요구사항:

> 실시간 주문 통계를 보여주고, 모든 주문 이벤트를 장기간 보관하고, 월별/지역별 매출 분석도 가능하게 하자.

구조:

```text
사용자 주문
    ↓
Spring Boot
    ↓
Kafka Producer
    ↓
order-topic
    ↓
┌──────────────────────────────┐
│            Kafka             │
└──────────────┬───────────────┘
               ↓
        Spark Streaming
          ↓          ↓
        HDFS          DW
       원본저장      집계저장
                      ↓
                 BI Dashboard
```

## 데이터 한 건의 이동

### 1) 사용자가 TV 구매

```json
{
  "orderId": 1001,
  "userId": 10,
  "product": "TV",
  "price": 1000000
}
```

### 2) Spring Boot가 Kafka에 전송

```text
order-topic
```

### 3) Kafka가 Partition에 저장

```text
Partition 1
Offset 100
```

### 4) Spark가 Kafka에서 읽음

```text
Kafka → Spark
```

### 5) Spark가 상품별 매출 계산

```text
기존 TV 매출 10,000,000
+ 새 주문      1,000,000
= 총 매출     11,000,000
```

### 6) 원본은 HDFS에 보관

```text
/data/order-events/2026/08/16/
```

### 7) 집계 결과는 DW에 저장

```text
daily_product_sales

date       product total_sales
```

# 25. HDFS와 DW는 왜 둘 다 필요한가?

## HDFS

원본/대용량 파일 보관에 강하다.

```text
JSON
CSV
Parquet
로그
이미지
대규모 원본 데이터
```

예:

```text
/data/log/2026/08/16/access.log
/data/order/2026/08/16/orders.parquet
```

## DW

SQL 분석하기 좋은 구조화된 데이터 저장에 강하다.

```sql
SELECT
    product,
    SUM(sales)
FROM daily_sales
GROUP BY product;
```

즉:

```text
HDFS = 대용량 파일 저장 중심
DW   = 분석 SQL 중심
```

# 26. Kafka와 HDFS도 둘 다 저장하는데 차이는?

Kafka도 디스크에 저장하지만 핵심 목적은 **이벤트 스트림 전달과 재처리**다.
HDFS의 핵심 목적은 **대용량 파일의 장기 분산 저장**이다.

예:

```text
Kafka
최근 며칠간 주문 이벤트
↓
실시간 Consumer들이 읽음

HDFS
수년치 주문 원본
↓
필요할 때 Spark가 다시 분석
```

# 27. Kafka와 Redis 차이

Redis:

```text
user:10 → 로그인 세션
product:100 → 상품 캐시
```

주요 목적:

```text
캐시
세션
빠른 Key-Value 조회
분산 락
```

Kafka:

```text
Event 1
Event 2
Event 3
Event 4
...
```

주요 목적:

```text
이벤트 스트림
메시지 전달
대량 데이터 파이프라인
```

# 28. 전체 비교표

| 기술           | 데이터를 저장? | 핵심 목적                  |
| -------------- | -------------: | -------------------------- |
| Redis          |              O | 빠른 조회 / 캐시           |
| Kafka          |              O | 이벤트 전달 / 스트리밍     |
| HDFS           |              O | 대용량 파일 장기 분산 저장 |
| Oracle/MySQL   |              O | 업무 트랜잭션              |
| Data Warehouse |              O | 대규모 분석                |
| Spark          |   처리 중 사용 | 대규모 분산 계산           |

Spark는 핵심적으로 저장소가 아니라 **계산 엔진**이다.

# 29. 백엔드 개발자 관점으로 보기

일반 Spring 서비스:

```text
React
 ↓
Spring Boot
 ↓
Oracle
```

이벤트 기반 구조를 추가하면:

```text
React
 ↓
Spring Boot
 ↓
Oracle
 ↓
Kafka
```

데이터 플랫폼까지 이어지면:

```text
React
 ↓
Spring Boot
 ↓
Oracle
 ↓
Kafka
 ↓
Spark
 ↓
HDFS / Data Warehouse
 ↓
BI / 분석
```

Spring 개발자가 Kafka까지 담당하고, 이후 Spark/HDFS/DW 영역은 데이터 엔지니어가 주로 담당하는 조직도 많다.

# 30. 최종 한 장 정리

```text
                  사용자
                    ↓
               React / App
                    ↓
               Spring Boot
                    ↓
                 Oracle
                    │
                이벤트 발생
                    ↓
                  Kafka
                    ↓
             ┌──────┴──────┐
             ↓             ↓
           Spark        일반 Consumer
             ↓          알림/포인트 등
        데이터 처리
          ↓      ↓
       HDFS       DW
     원본보관   분석 데이터
                  ↓
              BI Dashboard
```

가장 쉽게 외우면:

```text
Kafka = 데이터가 흐르는 통로
HDFS  = 대용량 파일 창고
Spark = 대용량 데이터 계산기
DW    = 분석하기 좋게 정리한 데이터 창고
```
